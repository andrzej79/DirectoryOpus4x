# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Directory Opus 4, the AmigaOS 3.x file manager, built from the GPL sources of DOpus 4.16
(Aminet `biz/dopus/DOpus416JRsrc.lha`, Jonathan Potter / GP Software, later Jacek Rzeuski).
The sources were written for GCC (geekgadgets, libnix) and PhxAss. This repo builds them with
vbcc/vasm/vlink, targeting the **68020 with soft float (no FPU instructions)**. First goal:
reproduce 4.16. Later goals: bug fixes and new features. Public repo: `andrzej79/DirectoryOpus4x`
(GPL-2.0-or-later). Nothing private goes in: no FTP logins, IPs, personal paths, or
references to private code.

## Build

Requires vbcc (0.9h) + vasm + vlink in `/opt/amiga_sdk/vbcc` on `PATH` with `VBCC` set,
NDK 3.2 in `/opt/amiga_sdk/NDK3.2R4` (paths hardcoded in `src/common.mk`), and the third-party
SDK files: run **`tools/fetch_sdk.sh`** once. It downloads them from Aminet into the git-ignored
`sdk/` and checks their SHA-256.

```
make            # all components -> build/<Component>/, then the dist tree build/DirectoryOpus4x/
make -j8        # same, parallel
make clean
make install    # copy dist tree to TARGET_DIR (~/Documents/Amiga/amiga_uae_disk/)
make ftp        # build + upload dist tree to Work:DirOpus4x/ (FTP_DIR=...)
make protos     # regenerate src/include/inline/*_protos.h via tools/fd2vbcc.py
make catalogs   # check src/catalogs/*.cd, compile the .ct files (part of make)
make lha        # build + pack the dist tree into release/DirectoryOpus417.lha (git-ignored)
make -C src/Config    # one component
```

- `make` does **not** clean first.
- Every object depends on all headers of its component and of `src/include` (vbcc writes no
  dependency files).
- **`make ftp` acts on a live Amiga.** Don't run it without the user's go-ahead. The login is in
  the git-ignored `ftp.local` in the root (format in `ftp.local.example`); `AMIGA_FTP_*` env vars
  override it.

## Layout

- `src/<Component>/Makefile`: one per component. Each includes `src/common.mk` (toolchain,
  flags, include paths, pattern rules).
- `src/<Component>/makefile.gcc`: the original makefiles, kept as reference only.
- Components:
  - `Program`: `DirectoryOpus`.
  - `Library`: `dopus.library`, used by all the others.
  - `Config`: `ConfigOpus`.
  - `DOpus_Disk`, `DOpus_Icon`, `DOpus_Print`: modules launched by the program.
  - `DOpusRT`.
- `src/pchg/`: PCHG library sources. They are compiled into Program, not built on their own.
  Its `makefile.gcc`/`smakefile` and the `i64/` directory (a SAS/C 64-bit helper, used only
  under `__SASC__`) are not built.
- `src/include/`: DOpus's own public headers (`dopus/`, `clib/`, `fd/`, `inline/`, `proto/`,
  `pragmas/`), plus our additions:
  - `compiler.h`: `REG()`, `D_S()`, NDK `NULL`, the `_exit` mapping.
  - `proto/all.h`: replaces the geekgadgets umbrella header.
  - `libraries/SysInfo.h`, `clib/sysinfo_protos.h`, `fd/sysinfo_lib.fd`: rebuilt, see README.
  - `inline/*_protos.h`: generated by `make protos`.
- `sdk/` (git-ignored, from `tools/fetch_sdk.sh`):
  - headers for xadmaster, xfdmaster, powerpacker, popupmenu, screennotify, cybergraphics
    and newmouse;
  - `sdk/stubs/pm_stubs.c` (popupmenu varargs functions, compiled into Program).

  Don't edit `sdk/`. Change `tools/fetch_sdk.sh` and re-run it.
- `icons/`: Workbench icons. `make` copies `DirectoryOpus.info` into the dist tree and clears its
  snapshot position there (`tools/amiSnapRemove.py`), so Workbench places it itself.
- Distribution layout: `DirectoryOpus`, `DirectoryOpus.info`, `C/DOpusRT`, `Libs/dopus.library`, `Modules/*`, `S/*.HLP`.
  This matches `look_dirs[]` in `src/Library/dopus_stuff.c` (`PROGDIR:` first).

## Code formatting

C sources and headers are formatted with clang-format, using `.clang-format` (LLVM based:
2-space indent, braces on their own line, `InsertBraces`, 120 columns). Format what you touch:
`clang-format-mp-22 -i --style=file <files>` (MacPorts), or Xcode's `xcrun clang-format`.
- `.clang-format-ignore` excludes `src/include/inline/*_protos.h`, which `make protos` generates.
- The `MAKE_ID(...)` IFF ID defines sit between `// clang-format off/on`. The NDK defines the
  same macros, and C only accepts a redefinition with identical spacing; reformatted, they fail
  with "macro redefined unidentically".
- A pure reformat must not change the generated code. To check one, build before and after and
  compare the binaries. `-S` output may differ only in the order of string constants (split
  literals), which `sort` on both listings shows.

## Porting conventions (vbcc)

Follow these when touching or adding code:

- **Register arguments**: `REG(a0, char *buf)`, from `compiler.h`. The GCC
  `register ... __asm("a0")` form and the SAS `register __a0` form don't compile with vbcc.
- **Attribute placement**: vbcc wants `__saveds`/`__chip` *before* the type:
  `__saveds char *Foo(...)`, `extern __chip USHORT data[]`. It doesn't accept
  `char *__saveds Foo` or `__saveds Foo(...)` with implicit `int`.
- **Implicit int**: a function that returns a pointer but has no prototype in scope is an error
  in vbcc ("invalid types for assignment"). Add a declaration to the component header; the
  modules use old-style `struct Gadget *addreqgadgets();` declarations next to their K&R
  definitions. Most code is K&R style. Keep that style in existing functions.
- **`NULL` is `0L`**: `compiler.h` redefines it after the libc headers. The code puts NULL in
  integer fields. Files that don't include a component header need `<compiler.h>` too.
- **Aligned stack structs**: DOS needs longword-aligned `FileInfoBlock`/`InfoData`. Use
  `D_S(struct FileInfoBlock, fib);`; then `fib` is a pointer. SAS `__aligned` doesn't exist in
  vbcc, and the vbcc stack is only word-aligned.
- **Asm alignment (PhxAss vs vasm)**: PhxAss treats `ds.w 0` as "align to word"; vasm in
  Motorola mode emits nothing, and it does not align `dc.w`/`dc.l` either. Use `even` /
  `cnop 0,4`. A `ds.w 0` in `dopuslib.a` once put the romtag init table at an odd address and
  crashed ramlib on `OpenLibrary()`. vasm's "instruction has been auto-aligned" warning means
  the label before it points to the unaligned address. Treat it as an error.
- **Chip data**: lives in the `.asm`/`.a` files as `section .data_chip,data,chip`. Without
  `,chip` the hunk is not loaded into Chip RAM.
- **64-bit ints**: `long long` is fine (`__SASC__` branches use `i64.h`; vbcc takes the GCC
  branches). vbcc's 68020 helpers (`__mulint64_020`) use 64-bit `mulu.l`, which the 68060 only
  has through 68060.library's emulation. That is fine for a Workbench program.
- **libnix leftovers**: `_exit()` maps to `_Exit()`, `stricmp` is now `Stricmp`, utility.library
  is auto-opened via `-lauto`, and `atoi` is a macro in vbcc's `stdlib.h` (`#undef` it before
  defining one).
- **Grep gotcha**: some sources (`Program/tasks.c`, `sdk/include/libraries/pm.h`) are Latin-1.
  The shell `grep` here is ugrep, which skips them as binary. Use `/usr/bin/grep` or `grep -a`
  when hunting across the tree, especially before scripted mass edits.

## Link details that matter

- **`dopus.library`**: `dopuslib.a` (`moveq #0,d0; rts`, then romtag and jump table) must be
  the first object. The library is linked with plain `vlink` (no startup code, `-nostdlib`),
  `-sc` merges all code into one hunk. Without `-sc` the C code and the asm code sit in separate
  hunks and the result needs `HUNK_RELRELOC32`.
  - The library has its own `_SysBase`/`_DOSBase`/... in `dopuslib.a`.
  - Only self-contained vc.lib parts (string, ctype, strtol, softfloat) may be used in the
    library: there is no C startup to initialise anything else.
  - Exported functions are in the `functable` of `dopuslib.a`. Their LVOs are in
    `src/include/fd/dopus_lib.fd`. Keep the table, the FD and `clib/dopus_protos.h` in sync, then
    `make protos`.
- **`DirectoryOpus`**:
  - Linked with plain `vlink` as `detach.o startup.o <objs>`. `src/Program/detach.asm` falls
    through into vbcc's `startup.o`, so its CODE section must stay a multiple of 4 bytes (an
    assembler `fail` checks this).
  - It does the Shell detach before any C init, because both processes share the data/bss hunks.
  - Stack size (`__stack`) and task name (`__procname`) are in `Program/data.c`. The 16 KB
    check in `main()` reads `pr_StackSize`, which only the detached process has.
- `Program/assembly.asm` is built, not `assembly.c` (an unfinished C port that duplicates
  `main7.c`). `getusage.c` is built, not `getusage.asm`. Both follow the original makefile.
- PopupMenu's `PMMenu(...) ... End` macros leave a call open across macro boundaries, which vbcc's
  preprocessor can't expand when `PM_MakeMenu` is itself a macro. So popupmenu varargs functions
  are real C stubs (`fd2vbcc.py --stubs`), not inline macros.

## Strings and catalogs

Each component has an enum of string IDs (`*strings.h`, ends in `STR_STRING_COUNT`), the English
texts in `default_strings[]` (`strings.c`), and a catalog description `src/catalogs/<name>.cd`.
The `.cd` IDs are automatic (`(//)`), so the position in the file is the ID. `make` fails unless
the `.cd` lists the enum in order and its texts equal `default_strings[]`.
- New strings go at the **end** of the enum, `default_strings[]` and the `.cd` (before
  `STR_STRING_COUNT`). Never insert, reorder or remove: catalogs, including users' old ones,
  address strings by number. A string no longer used stays as a placeholder (`STR_removed_*`).
- Changing an English text: change it in `strings.c` and the `.cd` together.
- Translations: `src/catalogs/<language>/*.ct`, ISO-8859-1 (edit with a Latin-1-safe tool). Add the
  Polish text along with a new string; other languages fall back to English until translated.
  A `.ct` entry is the name line, the text line, then `;` comment lines with the English.
- Help: English in `Program/DirectoryOpus.hlp` and `Config/ConfigOpus.HLP`, translations as
  `src/catalogs/<language>/DO_<language>.HLP` and `CO_<language>.HLP` (found by the locale's language
  name). Their bytes are copied as they are; the Polish ones use the AmigaPL code page.
- `catcomp.py` warns when a translation uses printf conversions the English text doesn't have.
- Build output: `Catalogs/<language>/*.catalog` in the dist tree. `tools/ftpput.py` sends file names
  as Latin-1 (`español`).

## Testing

There are no host-side tests: the binaries run only on an Amiga (or UAE). Build, then
`make ftp` (with the user's OK) or `make install` for UAE. Run from `Work:DirOpus4x/`.
Remove any old `dopus.library` from `LIBS:` and from memory first, or the old one is used.
If something misbehaves only in this build, compare against the GCC behaviour of 4.16.
vbcc 0.9h at `-O2` is known to miscompile some large code bases; building a suspect component
with `-O1` is a quick check.
